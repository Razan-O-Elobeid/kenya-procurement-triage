# Models and Evaluation Sprint Summary

Status as of 8 November 2026, for the Models and Evaluation Metrics sprint (10 November 2026).

All results below are **validation results from the 2018 to 2023 training period**. The 2024 to 2026 test period has not been used for any model comparison or selection.

## 1. Objective and data split

The project ranks Kenyan public contracts by review priority for auditors, using unsupervised anomaly detection and rule-based red flags. There are no verified corruption labels, so the system prioritizes contracts for human review. It does not classify corruption.

| Period | Contracts | Use |
|---|---:|---|
| 2018 to 2023 (training period) | 72,585 | All model comparison, tuning and selection, using `TimeSeriesSplit(5)` |
| 2024 to Aug 2026 (held-out test) | 36,399 | One final evaluation of frozen choices only |

**Validation folds**

- Five time-ordered folds.
- Training parts: 12,100 / 24,197 / 36,294 / 48,391 / 60,488 contracts.
- Each validation fold: 12,097 contracts.
- Everything fitted (indicators, supplier resolver, preprocessing, model) is fitted on each fold's training part only.

**Synthetic injection**

- 2% copies of clean validation contracts per type (241 per fold).
- Three types: value x 50, signing 200 days before close, and value x 5.
- The recall threshold is the 95th percentile of clean validation scores, so chance recall is 0.05.

Primary recall is the mean of the value x 50 and date recall, as defined in Phase 2.

**Notes**

- **R(c)'s value recall equals chance by design.** R(c) does not use a contract's own value.
- **For R(c) and the count, date copies have f3 and R(c) recomputed** with the fold's fitted references, as required by protocol section 5.
- **The naive count is coarse.** About 73% of validation contracts score 0, and the top-5% cut-off falls at a count of 2.
- **The count's date recall is partly mechanical.** One date shift fires both the pre-closure flag and f3.
- **f3 fires on 8.9 to 11.6% of training contracts in folds 1 to 4,** rather than 5%. This is because 6.3 to 7.4% of contracts share the decision-period value at the 95th percentile. Whole-day data creates ties. The pre-registered `>=` rule was kept unchanged.
- **Top-5% composition differs by method.**
  - In the baseline's top 5%, f3 fires on 78% of contracts and pre-closure signing on 77%, so timing dominates.
  - In R(c)'s top 5%, direct awards account for 43%.

## 4. Completed: stability analyses (protocol 7.1)

**Model-stage bootstrap** (Isolation Forest baseline configuration, 20 resamples per fold)

- Features and preprocessing are fitted once, in date order. Only the model's training rows are resampled, so no award is duplicated inside any history.
- Mean pairwise Spearman 0.993.
- Mean top-5% Jaccard against the full fit 0.871, which is about 93% of flagged contracts shared. The worst single resample gave 0.739.

**Quarter jackknife** (fold 5, full pipeline refitted with each quarter removed)

- Spearman: median 0.991, minimum 0.975.
- Top-5% Jaccard: median 0.867, minimum 0.822, which is about 90% shared.
- The largest effects come from dropping the most recent quarters, 2022Q4 to 2023Q3. These quarters are the largest and the closest in time to the validation period.

**R(c) reweighting** (200 flat-Dirichlet weight vectors over f1, f3, f4, f5)

- The full ranking is fairly robust: median Spearman 0.847, 5th percentile 0.628.
- The top 5% is not robust: median top-5% Jaccard 0.384, which is about 55% of flagged contracts shared, and 5th percentile 0.154.
- Fold 5 is the most sensitive (median Jaccard 0.284).
- More weight on f1 keeps the top set closer to equal weights (correlation +0.40). More weight on f5 moves it furthest away (-0.40).

**Interpretation**

- The baseline's flags are not an artifact of particular training contracts or periods.
- R(c)'s top list depends substantially on an unvalidated equal-weight convention.

These two results measure different things: sensitivity to data versus sensitivity to a definition.

## 6. Completed: isotree seed-overlap correction

- **The problem.** isotree seeds tree *i* with `random_seed + i` (`src/fit_model.hpp`, line 1756). In the first EIF run, protocol seeds 0 and 1 therefore shared 399 of 400 trees. Seed stability looked close to 1.0000 for every configuration, including the control, and the stability-first selection rule could not discriminate.
- **Detection.** The control (`ndim=1`) is the same algorithm as the scikit-learn baseline, yet showed stability of about 1.0000 against the baseline's 0.9916. A source check and a synthetic test confirmed the cause: isotree seeds 0 and 1 gave Spearman 0.9999, against 0.968 for seeds 0 and 1000.
- **Correction.** Protocol seed s is passed as `random_seed = 100000 x s` (isotree seeds 0 and 100000). Grid, folds, injections, metrics, thresholds and selection rules are unchanged.
- **Record.**
  - Deviations log, protocol section 12, dated 8 November 2026, marked "results seen before change: yes".
  - The first run is preserved in `results/model_evaluation/superseded_eif_seed_overlap/` and is not used for selection.
  - The corrected run's JSON records the seed mapping and the actual isotree seeds.

## 7. Limitations, deployment eligibility and provisional status

**Scientific limitations**

- **Synthetic recall is not corruption detection.** It measures how often an artificially distorted contract enters the top 5%. It does not show that real corruption is detected.
- **R(c), the naive count and synthetic labels are not ground truth.**
- **Value inflation is poorly detected by every method.** Value x 5 recall is about chance, and value x 50 is at most 0.18. All methods mainly detect unusual signing timing.
- **The EIF margin is modest.** It is +0.037 against a 0.02 tie margin. The selected configuration is the best of a four-way tie set, which slightly favors it. There is no formal significance test. The evidence is consistency across five time-ordered folds.
- **The final comparison will not be fully blind.** The Phase 2 baseline's test results were seen during Phase 2. The baseline is fixed, so this does not bias it.

**Deployment eligibility** (protocol 6.3)

- **EIF meets the cost target:** an end-to-end fit of about 3.7 s, against a 10-minute limit.
- **EIF is not yet deployable.** TreeExplainer does not support isotree. A model-agnostic explanation must first pass the validation checks in protocol section 8: additivity, correct target, agreement with TreeExplainer on the baseline, stability and run time.
- **Without a validated explanation method, EIF does not meet the pre-registered deployment eligibility criteria,** even if it remains best in the scientific ranking. In that case the research results would still report EIF as the scientific leader, and the deployed model would be the best-ranked model that does meet the criteria. Research reporting and deployment eligibility are kept separate.

**Provisional status.** EIF is the leader among the families evaluated so far. The cross-family selection is made on 18 November, after the remaining families, and frozen on 19 November.

## 10. Likely questions and answers

**Q1. How do you know there is no test-set leakage?**
All selection uses only the five time-ordered folds in 2018 to 2023. Every fitted component is fitted inside each fold's training part: indicators, supplier resolver, preprocessing and model. The validation code loads only the training period, and the rules were committed before the experiments ran. The Phase 2 baseline's test-period results (1,131 of 36,399 flagged) were already seen during Phase 2, so the test period has been scored before. The restriction applies to the new comparisons: the frozen configurations selected on 19 November are scored on the test period once, and those results are not used to choose or tune anything. Any later change is labeled exploratory.

**Q2. Without labels, what does synthetic recall tell you?**
It tells us how sensitive a ranking is to specific, known distortions: inflated values and signing before tender closure. It does not show that real corruption is detected. We use it to compare methods under identical conditions, alongside stability, agreement between methods, and a planned manual review of the top 50 contracts.

**Q3. Is the EIF improvement real or noise?**
The margin is +0.037 in primary recall, above the pre-registered 0.02 tie margin. EIF beats the baseline in all five time-ordered folds, and the `ndim=1` control matches the baseline. That is consistent with a benefit from the oblique splits, though it does not prove the cause. There is no formal significance test, and the selected setting is the best of a four-way tie, so we call the result provisional.

**Q4. How will you explain EIF predictions, given that TreeExplainer does not support isotree?**
We will test a model-agnostic SHAP permutation explainer against five pre-registered checks:

- additivity;
- whether it explains the actual ranking score;
- agreement with TreeExplainer when applied to the scikit-learn baseline;
- stability across background samples;
- run time on the review set.

If it fails, we will not present it as a validated explanation. The dashboard would then show the itemized red-flag scorecard instead.

**Q5. Why is value inflation detected so poorly, and what will you do about it?**
Value enters the model clipped to the training 1st and 99th percentiles, then log-scaled and standardized over all contracts. An inflated value either still falls inside the ordinary range of large contracts in other categories, or is capped at the 99th percentile, where only the binary `above_p99` flag distinguishes it. Next we test a relative-value feature: a contract's value compared with typical values in its category, fitted on training data only. It is pre-registered with a fixed adoption rule, and with the caveat that a feature built to catch value inflation gives only weak evidence when tested on injected value inflation.
